Git and Version Control Systems
Git is an example of a version control system.

Name a code hosting service that uses Git. Answer: GitHub is a hosting service that uses Git.

There are 3 states in Git that files can be in. What are these states? Answer: The three states in Git that files can be in are:

Modified: The file has been changed but not committed to the repository.
Staged: The changes to the file have been marked to be committed to the repository.
Committed: The changes to the file have been committed to the repository.
PR and repo are common abbreviations in the world of Git. What do they mean? Answer: PR stands for "Pull Request", which is a feature on code hosting platforms that allows developers to propose changes to a project and have those changes reviewed and merged into the codebase. A repo is short for "repository", which is a central location where code is stored and managed in Git.

What is the git command that updates the local repository with changes from the remote repository? Answer: The git command that updates the local repository with changes from the remote repository is "git pull".

What is the git command that gets the changes from the remote repository but doesn’t update your local repository? Answer: The git command that gets the changes from the remote repository but doesn't update your local repository is "git fetch".

What is the git command that updates the remote repository with local repository code? Answer: The git command that updates the remote repository with local repository code is "git push".

What does the git commit command need to work? Answer: The git commit command needs two things to work: a message and a set of changes to commit. The message is a brief description of the changes being committed, and the changes can be either files that have been modified or new files that have been added to the repository.
